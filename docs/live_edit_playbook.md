# Быстрые правки "на лету" в день мероприятия

Инструкция для двух конкретных правок, которые может понадобиться сделать
между прохождениями двух команд, без помощи разработчика: время встречи в
Главе 4 и аудио, которое проигрывается при правильном пароле на звонке.

Обе правки — это изменения напрямую в базе (Supabase) через её собственную
веб-панель. **Ничего не нужно пушить в git и ничего не нужно переразворачивать
на хостинге** — сайт читает эти данные из базы заново при каждом запросе,
правка подействует сразу же, без перезапуска чего-либо.

Выполняется в **Supabase Studio → SQL Editor** (вкладка слева, значок "SQL").
Оба запроса можно один раз сохранить там же как "Snippet" под понятным
названием, чтобы потом не искать и не перепечатывать — просто открыть и
поменять значение.

## 1. Время встречи (Глава 4, "Выясните время и место встречи")

```sql
update answer_field_accepted_values
set value = '21:30'  -- поставить нужное время
where field_id = (
  select af.id
  from answer_fields af
  join stages s on s.id = af.stage_id
  where s.slug = 'ch4_meeting_time' and af.field_key = 'time'
);
```

Меняете только время в кавычках (формат как сейчас — "20:00"), остальное не
трогаете. Нажимаете Run — готово.

## 2. Аудио на правильный пароль (звонок на 89859181998)

**Важно:** не перезаливайте файл под старым именем `correct.mp3` — Supabase
может закэшировать старую версию на некоторое время, и команда услышит не то,
что нужно. Каждый раз заливайте под новым именем и переключайте ссылку.

1. Сгенерировать mp3 (как обычно) и переименовать в что-то новое, например
   `correct_2130.mp3` — главное, чтобы имя отличалось от предыдущего
   использованного.
2. **Supabase Studio → Storage → бакет `call-audio` → Upload file** — залить
   этот файл.
3. Кликнуть на залитый файл → скопировать его публичный URL (или собрать
   вручную: `https://<ваш-проект>.supabase.co/storage/v1/object/public/call-audio/correct_2130.mp3`).
4. **Supabase Studio → SQL Editor**:

```sql
update call_phases
set audio_url = 'вставить скопированный URL'
where content_key = 'correct';
```

Старые файлы в бакете можно не удалять — они просто перестают
использоваться.

## Важно — не запускать `import_content.py` в день мероприятия

Обе таблицы (`answer_field_accepted_values` и `call_phases.audio_url`) при
каждом запуске `backend/import_content.py` полностью пересоздаются из
`data/quest_content.yaml` (и `data/audio/correct.mp3` для аудио). Если
между правками "на лету" ещё раз запустить импорт контента (например, чтобы
поправить что-то другое) — обе правки молча затрутся обратно на значения из
YAML. Пока в день мероприятия импорт не запускается — всё безопасно.
